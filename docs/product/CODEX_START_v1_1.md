# Сделано AI · Старт в Codex v1.1

## Подготовка проекта

1. Распакуйте ZIP в отдельную папку. В корне архива лежат `README_v1_1.md`, `AGENTS.md`, `.codex/` и `docs/product/`. Рабочие файлы перенесите в ветку проекта `zlw0x/ai_content_maker` с сохранением этих путей. Если правила проекта или конфигурация Codex уже есть, объедините изменения вручную. Инструкции Codex действуют из корня доверенного проекта.
2. Откройте корень репозитория в Codex. Сверьте рабочую ветку и `git status --short`. Сохраните существующие незакоммиченные изменения. Для изолированной работы подойдёт отдельный worktree.
3. Проверьте версии Node.js и команды в текущем `package.json`. Возьмите безопасные настройки из `.env.example` и репозиторных инструкций. Перед запуском зависимых от окружения тестов убедитесь, что используются `WAVESPEED_MODE=mock`, `PAYMENT_MODE=disabled`, `ALLOW_LIVE_PAYMENTS=false` и отдельная тестовая база.
4. Передайте Codex задание ниже. Первую задачу можно выполнить последовательно, если клиент не поддерживает проектные роли.

## Задание для вставки в Codex

> Продолжи работу над `zlw0x/ai_content_maker` по `docs/product/PRD_TECH_SPEC_v1_1.md` и `docs/product/BACKLOG_v1_1.csv`. Ты Coordinator. Прочитай `AGENTS.md` и `docs/product/SUBAGENT_WORKFLOW_v1_1.md`.
>
> Начни с A0. Зафиксируй ветку, коммит, текущие маршруты, состояние free-редактора, тесты, историю подтверждения WaveSpeed и действующие флаги. Параллельно поручай независимый аудит дизайна, провайдера и тестов максимум трём подагентам. Выдели каждому файлы и проверь результаты. Существующий код и ранее созданные данные сохраняй.
>
> Подготовь к ревью первый PR с минимальным локальным Recipe Engine, существующими шаблонами и mock-сценарием карточки. Утверди контракт до параллельных правок. Проверь, что ввод и выходы типизированы, текущий Free-экспорт работает, а повторы локальной обработки не создают дубликаты результата. Если базовые тесты красные, изолируй причину и зафиксируй, что относится к исходному коду и что к новому срезу.
>
> Используй mock, отключённые платежи и отдельную базу. Для настоящего WaveSpeed one-shot, внешних затрат, включения живых оплат и публикации нужны отдельные решения владельца. При `unknown` изучи состояние и журнал, платный POST повторно не отправляй. Итог — перечень изменений, пройденные проверки, блокеры и следующий ID задачи.

## Минимальная проверка первого PR

- После проверки локального окружения выполнить `npm run typecheck`, `npm run test:unit` и `npm run build`. Для `npm run test:smoke` и `npm run test:e2e` использовать запущенный mock-контур по README. Записывать реальные результаты и причины пропуска.
- Сравнить главную и `/apps/product-card` с базой. Проверить вход, готовый пример, экспорт без AI и отказ в доступе к чужому файлу. Прогнать сценарий рецепта с моками повторно с тем же ключом.
- Убедиться, что новые таблицы и поля совместимы со старыми заказами. Провести независимое QA-ревью. В описании указать A0, связанные ID, ограничения mock и следующий шаг A1. A1 закрывается только по критериям реального staging из PRD.
