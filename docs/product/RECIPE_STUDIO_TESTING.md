# Студия рецептов · Тестовый запуск

## Локальная проверка

Используйте отдельную PostgreSQL и приватную папку для файлов. Сначала примените миграции `npm run db:migrate`, затем запустите веб-приложение и worker. Для воспроизводимого прогона задайте:

```dotenv
WAVESPEED_MODE=mock
PAYMENT_MODE=disabled
ALLOW_LIVE_PAYMENTS=false
RECIPE_ORDERS_ENABLED=true
RECIPE_TRIAL_ENABLED=true
RECIPE_PAYMENT_MODE=mock
RECIPE_EMAIL_DELIVERY=mock
```

Откройте `/apps/recipes`. Студия показывает точную сумму из котировки и явно маркирует тестовый режим. Mock рендерит входное фото без AI-обработки. Кнопка тестового подтверждения переводит в очередь только заказ, созданный для mock worker. Для Trial код доступен в интерфейсе только при тестовой доставке, а подтверждение расходует отдельную квоту.

- `npm run test:unit` проверяет рендер, изоляцию адаптера и разбор биллинга.
- `npm run test:recipe-payments` использует изолированную мигрированную базу из `RECIPE_PAYMENT_TEST_DATABASE_URL` и подменяет запросы к ЮKassa.
- `npm run test:recipes` прогоняет HTTP-сценарий с реальным PostgreSQL и mock worker. `APP_ORIGIN` и `DATABASE_URL` должны указывать на тот же тестовый контур.

Из завершённого Trial «Удалить фон» откройте «Собрать карточку с этим фото». Карточки и реклама используют выданный владельцу PNG из приватного хранилища без повторной загрузки и вызова WaveSpeed. После окончания срока хранения потребуется исходное фото.

В Free «Подготовить фото» доступны заготовки Ozon 900 × 1200 и Wildberries 750 × 1000. Выбор включает кадрирование по центру. Перед публикацией проверьте кадр и правила категории. [Рекомендации Ozon](https://seller.ozon.ru/media/boost/glavnoe-o-perehode-na-foto-3-4-v-kartochkah-otvechaem-na-populyarnye-voprosy-prodavcov/), [требования Wildberries](https://seller.wildberries.ru/instructions/ru/ru/material/item-photo-rules-recommendations-and-common-mistakes).

## Внешние интеграции

- У `RECIPE_PAYMENT_MODE=yookassa-test` отдельные `YOOKASSA_TEST_SHOP_ID` и `YOOKASSA_TEST_SECRET_KEY`. Вебхук тестового магазина указывает на `/api/webhooks/recipe-yookassa`. Уведомление приводит к серверной сверке объекта по API. Worker этого контура работает в `WAVESPEED_MODE=mock`.
- Для отправки кода включите `RECIPE_EMAIL_DELIVERY=webhook` и задайте `RECIPE_EMAIL_WEBHOOK_URL` и отдельный `RECIPE_EMAIL_WEBHOOK_SECRET` длиной от 32 символов. Операторский HTTPS-адаптер принимает `POST` с `Authorization: Bearer …` и JSON-полями `to`, `subject`, `text`, отправляет письмо и возвращает HTTP 2xx. Код действует 10 минут.
- Режимы запуска заказов и Trial по умолчанию выключены. Фактические расходы WaveSpeed для тестов сверяются с записью биллинга по ID задачи. Подключение клиентских платежей, доставка писем на боевом домене и бета имеют отдельные условия допуска из [PRD](PRD_TECH_SPEC_v1_1.md).

## Откат и сверка

- При инциденте сначала остановите приём заказов через `RECIPE_ORDERS_ENABLED=false`. Worker продолжает получать уже принятые результаты. Заказы, которые ещё не отправлены провайдеру, остаются в очереди. Доступ к готовым файлам остаётся в медиатеке. Для остановки только новых пробных запусков используйте `RECIPE_TRIAL_ENABLED=false`.
- `SUBMISSION_UNCERTAIN` означает, что новый запрос может привести к повторному списанию. Сверьте время, модель и исходную запись с журналом WaveSpeed. При `OUTPUT_RECONCILIATION_TIMEOUT` используйте сохранённый prediction ID и проверенный CDN. Для `RECIPE_PROVIDER_FAILED` и `RECIPE_PROVIDER_OUTPUT` резерв Trial удерживается до сверки списания и возврата в WaveSpeed.
- Перед закрытой бетой нужны оператор поддержки, резервная копия и пробное восстановление PostgreSQL вместе с приватными файлами, тест доставки письма и платёж/отмена/возврат в тестовом магазине. Перед клиентскими платежами отдельно утвердите финальные цены, политику возвратов и финансовые документы.

### Команды оператора

Команды выполняются на сервере с `DATABASE_URL` нужного окружения.

- `npm run recipe:ops -- report` читает согласованный снимок очереди, числа успешных заказов и ошибок за 24 часа, незавершённых платежей и возвратов и бюджета Trial по дню UTC. В отчёте только агрегаты, без имён, изображений и ID клиентов. `providerQuotedUsd24h` — котировка провайдера по заказам с полученным ID, `budgetUsedUsd` — учёт бюджета с консервативными потолками. Для фактических списаний сверяйтесь с биллингом WaveSpeed.
- `npm run recipe:ops -- resume-result UUID` возобновляет только чтение сохранённого результата для заказа `OUTPUT_RECONCILIATION_TIMEOUT`. Команда сохраняет первоначальную дату отправки и ID провайдера. Сначала подтвердите актуальный хост CDN по ответу задачи.
- `npm run recipe:ops -- attach-result UUID PREDICTION_ID --history-checked` привязывает найденную задачу к заказу `SUBMISSION_UNCERTAIN` без ID. До выполнения сопоставьте заказ и задачу по журналу отправки, времени, модели и исходным данным. Доступность задачи в аккаунте WaveSpeed сама по себе не подтверждает принадлежность к заказу. Worker получит результат чтением существующей задачи.
- `npm run recipe:ops -- settle-trial UUID 0.004 --history-checked` фиксирует чистое списание после сверки платежа и возврата. Сумма `0` освобождает грант только после подтверждения отсутствия чистого списания. Пустой ответ свежего биллинга оставляет заказ на сверке. Повтор на ту же сумму идемпотентен. Сверка завершает заказ с ошибкой, поэтому сначала попытайтесь получить известный результат, если он ещё доступен.

### Приёмка закрытой беты

| Проверка | Доказательство |
| --- | --- |
| WaveSpeed и выдача | [Отчёт изолированного прогона](../LIVE_STAGING_CHECKLIST.md). Есть приватные результаты и постатейная сверка расходов |
| Восстановление | Тестовая копия PostgreSQL 17 восстановила 4 аккаунта, 2 заказа, 1 платёж и 7 приватных файлов. SHA-256 всех семи файлов совпали. Повторите проверку на выбранном для беты хосте |
| Поддержка | Назначьте дежурного с доступом к отчёту. Передавайте в инциденте время, внутренний ID заказа, код ошибки и ID провайдера. Клиентские файлы и платёжные секреты остаются в исходном контуре |
| Мониторинг | Проверяйте рост очереди, возраст старейшего заказа, `unknown`, зависшие возвраты и остаток бюджета Trial. При росте ошибок остановите новые заказы флагом и выполните сверку |
| Письмо | На изолированном хосте отправьте код на контролируемый почтовый ящик. Проверьте неверный код, затем успешное подтверждение и ровно один доступный Trial |
| Тестовый магазин | С отдельными тестовыми реквизитами проверьте успешную оплату, отмену и возврат после имитированного сбоя рендера. Повторите уведомление об оплате. Должен исполниться один рецепт, сумма и статус возврата должны совпасть с тестовым магазином |

Контрактные тесты и браузерные сценарии используют симуляцию оплаты. Сквозная проверка тестового магазина и внешней почты фиксируется отдельно. СБП и клиентские платежи имеют собственные условия допуска.

### Воронка беты

В закрытом окружении включите `RECIPE_FUNNEL_ENABLED=true` для веб-приложения. По умолчанию сбор выключен. Браузер хранит случайный ID визита в пределах вкладки, включая переход через вход. Сохраняются хеш ID, вид события и серверное время. Фотографии, поля макета и адрес почты в события не входят. Worker удаляет события и связь с котировками старше 30 дней.

Раздел `funnel30d` в `npm run recipe:ops -- report` считает первые последовательные действия в одной вкладке: открытие выбранного примера, запуск инструмента, клик скачивания Free, создание серверной Premium-котировки, подтверждение оплаты и выдачу. Клик скачивания показывает намерение скачать. Повтор фиксируется по второму оплаченному и выполненному заказу того же аккаунта в течение 30 дней после первого результата в воронке, включая заказ из другой вкладки. Это наблюдаемые повторы на дату отчёта. Недавние визиты ещё набирают срок наблюдения.

Сводка разделяет режимы WaveSpeed и отдельно показывает mock и тестовую ЮKassa. Сверяйте реальную маржу по фактическим списаниям, поступлениям и возвратам за период. Данные имитации служат для приёмки воронки.
