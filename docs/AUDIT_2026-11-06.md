# Технический аудит AI Content Maker — 06.11.2026

**Репозиторий:** `zlw0x/ai_content_maker`. Аудит текущей ветки `main` + исправления PR #13.

## Цель и метод

Проверить путь регистрации → расчёта цены → резервирования → отправки WaveSpeed → обработки результата → приватной выдачи, не выдавая mock за реально оплаченный inference. Прочитаны исходники Next.js, PostgreSQL migrations, worker, клиентский интерфейс, Docker Compose, тесты и официальные схемы WaveSpeed. Дополнительно развернут и протестирован **реальный Docker Compose stack в изолированном GitHub Actions runner**, а не на локальном Windows-ПК владельца.

**Прогон:** https://github.com/zlw0x/ai_content_maker/actions/runs/42227630219 — оба задания успешны: `web` и `compose-smoke`; PostgreSQL healthy, migrations, Next.js ready, worker, REST smoke, Playwright браузерные сценарии.

## Найденные проблемы, оценка и действия

### P0 — перед первым платным inference
1. **Pricing API:** код отправлял `{model_id,input}`, хотя актуальная официальная спецификация требует `{model_id,inputs}`. Отсутствие `inputs` может приводить к *базовой*, а не фактической цене — особенно для длительности видео и разрешения. **Исправлено в PR #13**, два теста проверяют plural `inputs`, а worker повторно проверяет реальную себестоимость до платного POST. Источник: https://wavespeed.ai/docs/pricing-api.
2. **Внешние зависимости не проверены:** ключ, provider balance, dynamic price, фактический output host и списание WaveSpeed не тестировались. Нужен новый ключ (прошлый был опубликован), отдельная staging БД, проверенный `OUTPUT_HOST_ALLOWLIST`, только одно платное изображение. Пока **NO-GO для реальной генерации**.
3. **Платежи клиентов не запущены:** `PAYMENT_MODE=disabled` по умолчанию, тестовая валюта не равна деньгам. **NO-GO для коммерческих пользователей**, но не блокирует изолированный staging.

### P1 — до публичной беты
4. **Зависшие задания:** `unknown` после неопределённого POST зарезервирует средства до ручной сверки; `processing` может опрашиваться очень долго. Нужны операторские метрики, SLA, безопасная сверка по prediction ID. Не вводить blind POST retry.
5. **Video memory:** output downloader буферизует до 80 MiB целиком в RAM, несмотря на уже потоковую отдачу файлов браузеру. Для серий видео заменить на streaming-to-disk с лимитом размера и атомарным сохранением.
6. **Хранилище:** `media` и `pgdata` — отдельные Docker volumes без подтверждённого теста восстановления. На первом VPS допустимо, перед пользовательской бетой проверить backup+restore.
7. **Учет себестоимости:** RUB quote использует конфигурируемый FX и markup, upstream ценник проверяется, но нет полноценной ежедневной сверки фактических USD списаний, себестоимости на job и alert по убыточности.
8. **Security:** backend проверяет ownership и exact host allowlist, но требуется аудит DNS rebinding / исходящих адресов, rate limiting в reverse proxy, email verification, password reset и защита публичной регистрации. Приватный CDN-URL провайдера не передаётся клиенту, оригинал скачивается на наш сервер.
9. **Provider schemas:** для Z-Image Turbo, Seedream V5 Pro, Wan 2.2 I2V/T2V, MiniMax Speech 2.6 HD, Real-ESRGAN основные поля подтверждены документацией; результат каждой из 10 Apps в live-режиме ещё не проверен. Описание background-swap как *точного сохранения объекта* нельзя гарантировать только prompt-редактированием.

### P2 — отложить до подтверждённого спроса
10. Объектное хранилище, выделенные очереди, воркеры горизонтально, сложная админка, многопровайдерная архитектура. Сейчас это преждевременно: один монолит, одна БД и один worker подходят для MVP.

## Что именно означает «локальный запуск»

В контексте этого аудита запуск *локальный для выделенного GitHub Actions runner*, но не для пользовательского Windows-ПК. На исполнителе ChatGPT нет Docker CLI и DNS-доступа к GitHub/npm, поэтому повторить весь runtime в его контейнере или зайти на чужой `localhost:3000` нельзя. Полный Compose-stack был **реально поднят** на GitHub runner, его тесты прошли, а ресурсы удалены после прогона. Это точнее и полезнее, чем выдавать простой `docker build` за работающий сервис.

## Go / No-Go следующего milestone

**Milestone: одна реальная Z-Image Turbo, 1024×1024.** Для его завершения обязательны:
- новый нераскрытый WaveSpeed API-ключ и доступный balance;
- чистая isolated staging DB и explicit cost caps (из `docs/LIVE_STAGING_CHECKLIST.md`);
- `npm run provider:check` с проверкой dynamic price и CDN host;
- ровно один `staging:one-shot` с подтверждённым разрешением расхода, без автоматического повтора;
- `generation_jobs.status=completed`, `media_assets` с локальной копией, download только владельцем, wallet reserve=0;
- сверка фактического списания в WaveSpeed History.

Без этого нельзя сообщать, что платная генерация работает. До первого результата НЕ подключать СБП, внешние GPU, несколько моделей или новую инфраструктуру.
