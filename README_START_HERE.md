# AI Content Maker — переносимый тест для Windows

**С чего начать:** откройте `01_START_HERE.cmd`, затем `02_RUN_ONE_TEST.cmd`. Это **полный проект**, со всеми исходниками Next.js, PostgreSQL, worker и Docker Compose. Установка Node.js, Git и локальной нейросети **не требуется**.

## Требования на другом ПК

- Windows 10/11 с включённой виртуализацией и работающим **Docker Desktop (WSL2)**; режим Linux containers
- Интернет для скачивания Docker-образов, npm-зависимостей и вызова WaveSpeed
- Желательно 4 ГБ свободной RAM и несколько ГБ свободного диска
- **Новый WaveSpeed API key** и положительный баланс на нём. Ключ, ранее отправленный в чат, нужно отозвать/заменить. Никому не пересылать файл `.env.staging`.
- Свободный локальный порт **3100**. База PostgreSQL наружу не публикуется.

**Внимание:** реальная модель WaveSpeed использует облачные GPU, видеокарта второго ПК не нужна.

## Шаг 1 — только установка и бесплатная проверка ключа

1. Распакуйте весь ZIP проекта в обычную папку, например `C:\AIContentMakerTest` (без OneDrive).
2. Установите и запустите [Docker Desktop](https://www.docker.com/products/docker-desktop/), дождитесь статуса **Engine running**.
3. Дважды щёлкните `01_START_HERE.cmd`.
4. Вставьте **новый** WaveSpeed API-ключ в скрытый ввод. Ввод не показывается и не попадёт в GitHub.
5. Скрипт создаст **локальный** `.env.staging`, уникальный пароль чистой БД, соберёт и запустит четыре контейнера (`db`, `migrate`, `web`, `worker`).
6. Скрипт откроет по API статус приложения и вызовет `provider:check`: **только проверка баланса и цены, без платной генерации**.

В случае успеха в консоли появятся `App is READY` и `Setup complete`. Адрес сайта: **http://localhost:3100**.

Среда полностью изолирована: Docker project `acm-staging`, отдельные volumes `acm-staging_staging_pgdata` и `acm-staging_staging_media`. **Не используйте обычный `docker compose up`** для этой версии теста: запускать следует именно CMD-скриптом.

## Шаг 2 — одна реальная генерация (~$0.005, фактическая цена проверяется)

1. Дважды щёлкните `02_RUN_ONE_TEST.cmd`.
2. Прочитайте условия и введите **`GENERATE`** большими латинскими буквами.
3. Сценарий проверяет чистоту staging БД, цену и баланс, регистрирует **отдельного тестового пользователя**, начисляет ему **только внутренние тестовые рубли**, создаёт одну котировку и отправляет **один платный запрос** `wavespeed-ai/z-image/turbo` (1024×1024).
4. В терминале появятся `Staging account` с email и временным паролем. **Сохраните их в надёжном месте, не пересылайте журнал целиком**.
5. После `LIVE_STAGING_SUCCESS` откройте [личный кабинет](http://localhost:3100/account), войдите с этими данными, затем откройте [медиатеку](http://localhost:3100/library). Там должен быть полученный файл, скачанный с WaveSpeed в наше приватное хранилище.

**Лимиты:** предполагаемая себестоимость около **$0.005**, проверяемый предел одного задания **$0.01**. Общая RUB-котировка ограничена **1000 копейками внутреннего тестового баланса**, внешняя оплата клиентов выключена. Сервис может пересчитать цену при реальной отправке; результат и фактическое списание проверяйте в WaveSpeed History.

**Не запускайте `02_RUN_ONE_TEST.cmd` повторно**, если запрос завершился ошибкой, таймаутом или статусом `unknown`: модель могла уже принять задание и списать стоимость. Сценарий не разрешит запуск на базе с уже созданными пользователями.

## Дополнительные команды

- `03_STATUS.cmd` — состояние контейнеров и последние логи worker.
- `04_STOP_KEEP_DATA.cmd` — остановить окружение, **сохранив** тестового пользователя, результаты и базу. Для повторного запуска используйте `01_START_HERE.cmd`.
- `compose.staging.yaml` — отдельный контейнерный стек. Не редактируйте, если не требуется.
- `.env.staging.example` — пример конфигурации без секретов.
- `.env.staging` — созданный локально файл **с ключом и паролем БД**. Никогда не публикуйте.

## Диагностика

| Симптом | Решение |
|---|---|
| `docker` not found | Установить Docker Desktop, закрыть/открыть CMD, запустить 01 |
| Docker engine unavailable | Открыть Docker Desktop и дождаться запуска Linux engine |
| Port 3100 already allocated | Закрыть другое приложение на 3100; не запускать две staging-копии |
| Provider preflight failed | Проверить новый ключ, баланс WaveSpeed, актуальную стоимость модели; **не** запускать 02 |
| `OUTPUT_HOST_NOT_ALLOWED` | Результат мог быть уже оплачен! Установить в `.env.staging` **точный проверенный** hostname результата, перезапустить 01 для применения; worker повторяет безопасный GET, но **не** запускать 02 повторно |
| `unknown` / timeout | Проверить `03_STATUS.cmd`, WaveSpeed History и ID задания. **Не повторять отправку POST** |
| No files after successful task | Проверить worker логи и allowlist CDN, срок доступности URL у WaveSpeed |

Точный hostname CDN зависит от реального ответа WaveSpeed. В шаблоне указан `d2h7xmz5gqybh9.cloudfront.net`, полученный из результата теста 9 ноября 2026 года. При другом хосте проверьте адрес по GET уже созданной задачи. После обновления allowlist worker скачает тот же результат.

## Что проверено и что нет

9 ноября 2026 года изолированный тест приложения подтвердил один реальный вызов Z-Image Turbo. Котировка и списание WaveSpeed совпали и составили $0,005. Владелец заказа скачал JPEG через приватный маршрут, запрос без входа вернул HTTP 401. Внутренний резерв списан одной операцией. Когда ответ пришёл с другим CDN, загрузка продолжилась после проверки точного хоста через GET уже созданной задачи.
